# Pass 1 — 論点の切り出し

## このパスの役割

文字起こしを論点単位に分割し、**境界と見出しだけ**を出力する。

出力が10行程度で済むため、人間がこの時点で粒度を直せる。
論点の適正粒度は3回ほど回さないと決まらないので、その調整をここで安く吸収する。

---

## 入力

- `meetings/MTG-YYYYMMDD/transcript.md` — 文字起こし（話者役割つき・タイムスタンプつき）
- `role-mapping.yaml`

## 出力

- `meetings/MTG-YYYYMMDD/segments.yaml`

---

## プロンプト本体

以下をそのまま指示として渡す。

---

あなたは会議の文字起こしを論点単位に分割する。**内容の要約・抽出は一切しない。**

### 論点の定義

**1論点 = 1つの問いに対する議論。**

- ○ 「認証方式をどうするか」= 1論点
- ✗ 「認証方式とデータ移行のスケジュール」= 2論点に分ける
- 決定が2つ出ても、問いが1つなら1論点のまま分割しない
- 何も決まらなかった区間（報告・雑談）も論点として残す。種別で区別する

### 境界のシグナル

次のいずれかが現れたら論点の境界とみなす。

- 議題の明示的な移行 — 「次の話ですが」「では〇〇について」「一旦これはこれで」「話は変わりますが」
- 決定成立後の話題転換 — 「じゃあそれで」と合意した直後に別の話題へ移る
- 30秒以上の沈黙
- 参加者の入退室の言及 — 「〇〇さん入られました」「先に失礼します」

### 種別の判定

各論点に次のいずれかを付ける。

| 種別 | 判定基準 |
|---|---|
| `議論` | 選択肢が複数出た、または結論を出そうとしている |
| `報告` | 一方向の状況共有。問いがない |
| `確認` | 既に決まったことの確認、認識合わせ |
| `雑談` | 議題と無関係 |

`報告` と `雑談` は後続パスで決定事項の抽出をスキップするため、判定を甘くしないこと。
選択肢が1つでも提示されていれば `議論` とする。

### 見出しの付け方

- 体言止めで、その論点の**問い**が分かる形にする
- ○ 「認証方式の選定」「データ移行のスケジュール」
- ✗ 「認証について」「いろいろな話」「その他」
- 20文字以内

### 出力形式

YAML のみを出力する。前後に説明文を書かない。

```yaml
meeting: MTG-20260918
segments:
  - seq: 1
    title: 前回アクションの確認
    種別: 確認
    時刻: "00:00:00 - 00:06:40"
    参加役割: [顧客PM, 開発リーダ, 開発メンバー]

  - seq: 2
    title: データ移行のスケジュール
    種別: 議論
    時刻: "00:06:40 - 00:21:10"
    参加役割: [顧客PM, 開発リーダ]

  - seq: 3
    title: 認証方式の選定
    種別: 議論
    時刻: "00:21:10 - 00:34:52"
    参加役割: [顧客PM, 開発リーダ, 開発メンバー]
```

### 禁止事項

- 発言内容の要約を書かない
- 決定事項・未定事項・アクションを抽出しない（Pass 3 の仕事）
- 逐語を引用しない
- 論点を **3件未満 または 20件超** に分割しない。その範囲に収まらない場合は、
  出力の末尾に `# 逸脱理由: <1行>` をコメントとして付ける
- 未知語・用語の指摘をしない（Pass 2 の仕事）

### 未知の役割ラベル

`role-mapping.yaml` の `roles` に無い役割ラベルが現れた場合、
`参加役割` にはそのまま記載し、出力末尾に次を付ける。

```yaml
# 未登録の役割ラベル: [〇〇]
```

---

## 人間の確認（ここが重要）

出力された `segments.yaml` を見て、次だけ判断する。

1. **粒度** — 分割しすぎ／粗すぎがないか。直す場合は「seq 3 を認証方式と権限設計に分けて」と指示して再生成
2. **種別** — `議論` が `報告` に誤分類されていないか（逆方向の誤りは害が小さい）
3. **未登録の役割** — あれば `role-mapping.yaml` に追記

ここを通してから Pass 2 に進む。
