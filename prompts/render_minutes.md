# 議事録のレンダリング

## 位置づけ

**議事録はカードから毎回生成する。ファイルとして保存しない。**

保存すると、カードを更新したときに議事録が古くなり、二重管理が復活する。
カードが唯一の真実で、議事録はその射影。

「最終議事録」は固定物ではなく、**リーダ承認時点のスナップショット**である。
顧客提出が必要なら、その時点で PDF 等に出力して渡す。
渡した後にカードが更新されても正常な状態（提出版は過去のスナップショット、カードが現在）。

---

## 入力

- その会議で生成・更新された LOG / DEC / Q / ACT
- 前回会議から引き継がれた ACT（status が `完了` `取り下げ` 以外）
- 昇格が承認された CON / ASM

## 出力

2種類を作り分ける。同じカードから別々にレンダリングする。

| 版 | 読者 | 生々しい情報 |
|---|---|---|
| 社内版 | 自社メンバー・リーダ | すべて出す |
| 顧客提出版 | 顧客 | **出さない**（下記） |

---

### 社内版の要点

- **`記録なし` と `推測` を隠さない。** 言語化されなかった量が見えることに価値がある
- 末尾の「記録の状態」で、この会議の記録品質を可視化する
- 逐語引用を1つは入れる（判断の空気が残る）
- LOG 本文は `<details>` で畳む（読む人の負荷を下げる）

## 顧客提出版

```markdown
# 定例会議 議事録

日時: 2026-09-18
出席: （社名・役割）

## 前回アクションの結果

| 内容 | 担当 | 期限 | 状況 |
|---|---|---|---|

## 決定事項

### 認証を自社実装せず OIDC に寄せる

（決定内容と、顧客と合意した理由）

本件で検討し、採用しなかった方式:

| 案 | 採用しなかった理由 |
|---|---|
| 既存ADへの直結 | VPNが固定IPのみであるため |

## 確認事項

| 内容 | 確認先 | 期限 |
|---|---|---|

## アクション

| 内容 | 担当 | 期限 |
|---|---|---|

---

本議事録は、送付後3営業日以内にご異議のない場合、記載内容をもって確定とさせていただきます。
```

### みなし確定の一文を必ず入れる

顧客提出版の末尾に上記の一文を定型で入れる。

**理由**：相手方が確認・同意していない記録は、訴訟で「自己に都合の良いことしか書かれていない」
メモとして扱われ水掛け論を招く。「議事録回覧後、一定期間内に異議がなければ確定する」
ルール設定が有効とされている（伊藤雅浩弁護士, 2017）。実務の相場は3営業日。

異議なく確定したら、その日を各 DEC の `確定日` に書き戻す。
これが25分の運用に足す唯一の追加作業（送信1回と、次回の書き戻し）。

### 会議体名を明記する

「決定事項の重みは会議の位置づけで異なる」ため、契約書で定義した会議体名
（定例WG / ステアリングコミッティ等）を議事録の冒頭に書く。
DEC の `会議体` フィールドがこれに対応する。役割だけでは契約上の会議体定義と接続できない。

### 顧客提出版で出さないもの

| 出さない | 理由 |
|---|---|
| `信頼度: 推測` の決定 | 未確認のものを合意事項として提示できない。`確認事項` に回す |
| `却下理由: 記録なし` の代替案 | 記録の不備を対外文書に書けない。その行ごと省く |
| `信頼度: 言及のみ` の代替案 | 同上 |
| 硬度・所在・信頼度などの内部メタ | 内部管理情報 |
| カード ID | 内部管理情報（社内版のみ） |
| 自社側の制約 CON（所在=自社側） | 自社の都合を対外に開示しない |
| LOG 本文・逐語引用 | 発言録は原則出さない |
| 「記録の状態」セクション | 内部品質情報 |

**顧客側の制約（所在=顧客側）は出してよい。** 顧客自身の事情であり、
合意の前提として明記しておく方が後の齟齬を防ぐ。

### 表記の変換

- 役割 → 社名（`顧客PM` → `〇〇株式会社`）に丸める
- 「却下」→「採用しなかった」
- 「作らない」→「本フェーズの対象外」
- 断定を避ける箇所は残さない（未確定のものは `確認事項` に移す）

## プロンプト本体

以下をそのまま指示として渡す。

---

あなたはカード群から議事録をレンダリングする。**内容の追加・推測は一切しない。**

### 守ること

1. **カードに書かれていないことを書かない。** 空欄は空欄として扱う
2. `なぜ` が空欄の決定は、決定内容だけを書く。理由を補完しない
3. `却下理由: 記録なし` は、社内版では **記録なし** と太字で明記する
4. 逐語引用は LOG カードから正確に写す
5. 前回から引き継がれた ACT を必ず冒頭に置く（定例で最初に確認される項目）
6. 版の指定（社内版 / 顧客提出版）に従い、上の除外ルールを厳守する

### 禁止事項

- カードにない決定・理由・アクションを書く
- 空欄を「特になし」で埋める（`未記入` と `該当なし` は別の意味）
- 顧客提出版に `推測` `記録なし` `言及のみ` のものを含める
- 顧客提出版に役割ラベル・カード ID・逐語引用を残す
- 議事録をファイルとして保存する（生成して渡すだけ）
- カードを更新する（レンダリングは読み取り専用）

### 版の指定

`版: 社内` または `版: 顧客提出` を指示に含める。指定がなければ社内版とする。
