# Pass 1 — 論点の切り出し

共通規約は `CLAUDE.md` が正典。以下がこのパスの判定基準。

文字起こしを論点単位に分割し、**境界と見出しだけ**を出力する。**要約・抽出は一切しない。**
出力が10行程度で済むので、人間がこの時点で粒度を直せる。適正な粒度は3回ほど回さないと
決まらないので、その調整をここで安く吸収する。

## 手順

1. 対象の会議を決める。無ければ `projects/<slug>/meetings/MTG-YYYYMMDD/` を作り、
   `transcript.md` を置いてもらう
2. `role-mapping.yaml` を読む（役割ラベルの表記を合わせるため）
3. `meetings/MTG-YYYYMMDD/segments.yaml` に書き出す
4. **人間に粒度の確認を求めて、そこで止まる**

## 論点の定義

**1論点 = 1つの問いに対する議論。**

- ○ 「認証方式をどうするか」= 1論点
- ✗ 「認証方式とデータ移行のスケジュール」= 2論点に分ける
- 決定が2つ出ても、問いが1つなら分割しない
- 何も決まらなかった区間（報告・雑談）も論点として残す。種別で区別する

## 境界のシグナル

- 議題の明示的な移行 — 「次の話ですが」「では〇〇について」「一旦これはこれで」
- 決定成立後の話題転換 — 「じゃあそれで」の直後に別の話題へ移る
- 30秒以上の沈黙
- 参加者の入退室の言及 — 「〇〇さん入られました」「先に失礼します」

## 種別の判定

| 種別 | 判定基準 |
|---|---|
| `議論` | 選択肢が複数出た、または結論を出そうとしている |
| `報告` | 一方向の状況共有。問いがない |
| `確認` | 既に決まったことの確認、認識合わせ |
| `雑談` | 議題と無関係 |

`報告` と `雑談` は後続パスで決定事項の抽出をスキップするため、**判定を甘くしない**。
選択肢が1つでも提示されていれば `議論` とする。

## 見出しの付け方

体言止めで、その論点の**問い**が分かる形。20文字以内。

- ○ 「認証方式の選定」「データ移行のスケジュール」
- ✗ 「認証について」「いろいろな話」「その他」

## 出力形式

YAML のみ。前後に説明文を書かない。

```yaml
meeting: MTG-20260918
segments:
  - seq: 1
    title: 前回アクションの確認
    種別: 確認
    時刻: "00:00:00 - 00:06:40"
    参加役割: [顧客PM, 開発リーダ, 開発メンバー]

  - seq: 2
    title: 認証方式の選定
    種別: 議論
    時刻: "00:06:40 - 00:21:10"
    参加役割: [顧客PM, 開発リーダ]
```

`role-mapping.yaml` の `roles` に無い役割ラベルは、`参加役割` にそのまま記載したうえで
末尾に `# 未登録の役割ラベル: [〇〇]` を付ける。**勝手に既存の役割へ寄せない。**

## 禁止事項

- 発言内容の要約を書く
- 決定事項・未定事項・アクションを抽出する（Pass 3 の仕事）
- 逐語を引用する
- 未知語・用語を指摘する（Pass 2 の仕事）
- 論点を **3件未満 または 20件超** に分割する。その範囲に収まらない場合は、末尾に
  `# 逸脱理由: <1行>` を付ける

## 人間の確認（ここが重要）

`segments.yaml` を見て、次だけ判断してもらう。

1. **粒度** — 分割しすぎ／粗すぎがないか。「seq 3 を認証方式と権限設計に分けて」と
   指示を受けたら再生成する
2. **種別** — `議論` が `報告` に誤分類されていないか（逆方向の誤りは害が小さい）
3. **未登録の役割** — あれば `role-mapping.yaml` に追記する

ここを通してから Pass 2 に進む。飛ばすと後戻りが高くつく。
