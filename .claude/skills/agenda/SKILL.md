# 次回アジェンダ — 議題の射影を出す

共通規約は `CLAUDE.md` が正典。以下がこのスキルの判定基準。

アジェンダは「その会議に載る議題（AGD）と、その下にぶら下がる決定・未決・アクション」の
射影。前回までの未決は議題の下に持ち越され、決着するまで自動で残る。

- **内容の追加・推測は一切しない。** 材料に無いことを書かない
- **ファイルには保存しない。** 会話の中に出す（保存すると、カードを更新したとき古くなる）
- **このスキルがカードに書くのは、議題の起票と、人が言った議題の締めだけ**

## 出す

1. `python3 tools/kime.py agenda-input`。**会議 ID は要らない**（省略すると「次回」として
   閉じていない議題を全部出す）。次の会議の ID が決まっていて、その会議として出したいとき
   だけ `--meeting MTG-YYYYMMDD`（まだ無くてよい）
2. **材料の末尾に出る「アジェンダの骨格」の見出しを、その順で使って書く**
3. 会話の中に出す

## 議題を足す（「これを決めたい」と言われたら）

会議の前でも、会議の冒頭でも同じ。**アジェンダに手で書き足さず、議題カードとして起票してから**
材料を出し直す（書き足すと射影でなくなり、次回に残らない）。

1. `AskUserQuestion` で聞くのは **議題の文言と、提起者（役割）の2つだけ**。
   会議は聞かない — `予定会議` が空なら次回に載る。「◯月◯日の会議で」と会議が
   言われたときだけ `--meeting` を付ける
2. 返ってきた言葉のまま起票する:
   `python3 tools/kime.py new agenda --title "…" --role 役割 --write`
3. 「出す」からやり直す

文言を言い換えない・まとめない・「〜について」に丸めない。議題は決定ではないので、
結論めいた書き方（「〜とする」）にもしない。

## 議題を閉じる（人が言ったときだけ）

「この議題はもう決まった」「取り下げる」と**人が言ったときだけ**
`python3 tools/kime.py update AGD-NNN --set status=決着 --set 決着日=YYYY-MM-DD`（または `取り下げ`）を
実行する。`決着日` はその判断をした会議の日（status だけでは「いつ閉じたか」が残らない）。
通常は確認②の 2-5 で締める（`/review`）。目安（未決が残っているか）を見せてよいが、
決めるのは人。未決の問いが残ったまま決着にすると lint の `agd-closed-open` が鳴る —
それは計器で、消すために Q を閉じない。

## 順序を変えない

冒頭は **`なぜ` が未記入の決定**。これは書式の都合ではなく、「書かないことに付けたコスト」
そのもの。未記入のあいだ、その決定は制約・前提へ昇格できない。順序を変えると、
このコストが効かなくなる。

その後の順は骨格のとおり（正本は `ontology.yaml` の `agenda.sections`。ここに写さない）。

## 議題の書き方

- 議題ごとに「これまでの決定」「未決の問い」「未完了のアクション」を材料のまま並べる
- 持ち越しの議題はそうと分かるように書く。材料の「扱ったが結論なし」「扱えず」をそのまま使う
  （前者は続きから、後者は最初から話す議題。言い換えると次の会議の入り方が変わる）
- 「スコープの確認」は `スコープ: 判定保留` の決定の射影。Q カードは無いので、決定の ID と問いの文面・確認先を材料のまま出す
- 「議題に紐づかない未決の問い」も落とさない。議題が決着しても問いは残りうる
- 結論が出なかった議題を Q に言い換えて足さない。開いた議題が「まだ決まっていない」を表す

## 四半期の棚卸し

年4回。骨格の「前提の棚卸し」の節に出た前提を、signpost と並べて出す（どの前提を載せるかは CLI が絞っている。自分で選び直さない）。
「崩れたか」だけを人が見る（5分）。全件を追跡しない。判定の書き戻しは `/review` が持つ。

## このビューが読まれないなら

引かれない記録は死んでいる。アジェンダが定例の冒頭で読まれていないなら、
それ自体が「この仕組みが定着していない」という所見。カードを増やしても直らない。
