# Pass 3 — DEC / Q / ACT の抽出

共通規約は `CLAUDE.md` が正典。判定基準の正本は `decision-guide.md`、
手順の正本は `prompts/pass3_extract.md`。以下は本スキル固有の手順。

## 必ず1論点ずつ処理する

**全論点を一度に渡さない。** コンテキストが伸びると逐語引用が要約され始め、
引用が崩れる。引用が崩れると検証機構が死ぬ。LOG カード1枚ごとに反復実行する。

各回に渡すもの:
- LOG カード1枚
- そのセグメントの `種別` と、会議全体での位置（第何セグメント / 全何セグメント）
- `role-mapping.yaml`
- `decision-guide.md`
- 既存の `questions/*.md` と `actions/*.md` の一覧（id と title だけ。同一性判定用）

`種別` と位置を必ず渡すこと。会議のどの局面かは、話者情報より強い信号になる。

## 手順

1. `python3 tools/giji.py lint --check log-format --root <案件>` で LOG の形式を確認
2. LOG の `種別` が `報告` / `雑談` なら **DEC は抽出しない**（ACT と Q のみ）
3. `prompts/pass3_extract.md` の指示をそのまま実行する
4. `python3 tools/giji.py new decision --write` などで採番してカードを作る
5. 全論点を終えたら `python3 tools/giji.py verify-quotes --fix` を回す
6. `python3 tools/giji.py lint` で error 0 を確認する

## 絶対に書かないもの

- `なぜ` / `受容した不利` / `確認方法` — **空欄のまま出す**
- `代替案[].却下理由` — 発話から取れなければ `記録なし`
- ACT の `担当` / `期限` — **空欄が正常な出力**

理由を合成すると一見正しく見え、人間が通してしまう。これが最大の失敗モード。

## 迷ったら DEC ではなく Q

- 決定権のない役割の発言だけでは DEC を起票しない
- 「前向きに検討します」「持ち帰ります」「調整します」は必ず Q
- `範囲` が判定できなければ `判定保留` にし、対応する Q を立てる

## このパスでやらないこと

CON / ASM / TERM を作る（Pass 4 の人間承認を経たものだけが存在する）。
ストック層は寿命が長く、誤りのコストが桁で違う。
