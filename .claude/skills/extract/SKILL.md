# Pass 3 — DEC / Q / ACT の抽出

共通規約は `CLAUDE.md` が正典。何を DEC とするかの正本は `decision-guide.md`。
以下がこのパスの正本。

**制約（CON）と前提（ASM）はこのパスで作らない。** Pass 4 の人間承認を経たものだけが
存在する。ストック層は寿命が長く、誤りのコストが桁で違う。

## 必ず1論点ずつ処理する

**全論点を一度に渡さない。** コンテキストが伸びると逐語引用が要約され始め、引用が崩れる。
引用が崩れると検証機構が死ぬ。LOG カード1枚ごとに反復実行する。

各回に読むもの:

- LOG カード1枚
- そのセグメントの `種別` と、会議全体での位置（第何セグメント / 全何セグメント）
- `role-mapping.yaml`
- `decision-guide.md`
- 既存の `questions/*.md` と `actions/*.md` の一覧（id と title だけ。同一性判定用）

`種別` と位置を必ず見ること。Murray & Renals (2008) のアクション項目検出では、特徴クラス別の
AUROC が **構造 0.93 / 語彙 0.80 / 発話長 0.80 / 話者 0.69 / 韻律 0.64** で、
**「会議のどの局面か」が話者情報より強い信号**だった。役割ルールを単独の決め手にしない。

## 手順

1. `python3 tools/giji.py lint --check log-format --root <案件>` で LOG の形式を確認
2. LOG の `種別` が `報告` / `雑談` なら **DEC は抽出しない**（ACT と Q のみ）
3. 下記の判定基準に従い、1論点ずつ抽出する
4. `python3 tools/giji.py new decision --write` などで採番してカードを作る
5. 全論点を終えたら `python3 tools/giji.py verify-quotes --fix` を回す
6. `python3 tools/giji.py lint` で error 0 を確認する

## 最重要の原則 — 非対称に設計する

**迷ったら DEC ではなく Q か LOG に落とす。そして候補は多めに出す。**

誤起票の害が非対称である。嘘の DEC は半年後まで嘘のまま残り、それを根拠に仕様が書かれる。
余分な Q は次回定例で消える。害の大きさが違うので、判断を DEC 側に寄せてはならない。

同時に、**高再現・低精度に振る**。決定サブ対話の検出は **再現 0.88 / 精度 0.43**（F1 0.58）
まで届くのが実測（Fernández ほか 2008）で、「拾いすぎて人が捨てる」形が機械の得意な形と
一致している。逆向き（精度を上げて人が足す）は機械も人間も苦手。

具体的には次を守る。

1. **決定権のない役割の発言だけでは DEC を起票しない。必ず Q に落とす**
2. 引用できる発言がない決定は起票しない
3. 「決まりそうだった」「そういう流れだった」で起票しない
4. **迷ったものは捨てずに Q として出す**（人間が捨てる前提）

## 欠落ガード — これが最大のエラー源

会議要約の人手エラー注釈では、**欠落 89% に対して幻覚 26%**（Kirstein ほか 2024、IAA 0.81）。
**欠落は幻覚の3倍以上多い。** そして引用検証は「言っていないことを言った」を検出するが
「**言ったことを落とした**」を一切検出しない。

だからここで守る。

> **`種別` が `議論` または `確認` のセグメントでは、DEC / Q / ACT を合わせて最低1件出す。
> 1件も出せない場合は、出せない理由を1行書く。**

```yaml
extraction_empty_reason: 前回の決定内容の読み上げのみで、新たな判断は現れなかった
```

理由が書けない、あるいは理由が「特になし」に留まるセグメントは `review_required: true` を
立てる。人間が②の確認でそこを見る。

`種別` が `報告` / `雑談` のセグメントは0件でよい（理由も不要）。

## 役割別の解釈ルール

`role-mapping.yaml` で役割を `所属` × `決定権` の2軸に引き当ててから解釈する。

| 発言パターン | 顧客側・決定権あり | 自社側・決定権あり | 決定権なし（両側共通） |
|---|---|---|---|
| 「じゃあ〜で」「〜でいきましょう」 | **DEC 確定** | DEC（種別=技術判断） | **Q に落とす** |
| 「今回はスコープ外」「次フェーズで」 | DEC（`作らない` に記入） | DEC候補 + Q を併記（顧客承認待ち） | Q |
| 「一旦置いといて」「保留で」 | Q（確認先=その役割） | Q | LOG のみ（提案の取り下げ） |
| 「〜だと厳しい」「〜がネック」 | Pass 4 へ制約候補として渡す | Pass 4 へ制約候補として渡す | LOG のみ（難易度の表明） |
| 「〜やっておきます」「こちらで確認します」 | ACT（担当=その役割の社名） | ACT（担当=その役割の社名） | ACT（担当=その役割の社名） |
| 「〜という手もある」 | 代替案の言及として記録 | 代替案の言及として記録 | 代替案の言及として記録 |

**アクションだけは決定権を問わない。** 誰が言っても約束は約束であり、担当は役割から引いた
社名になる。

## 引用はどの発話から採るか（優先順位）

決定に関わる発話は4種に分かれる（Fernández ほか 2008）。引用はこの優先順位で採る。

| 優先 | 種類 | 例 | 性質 |
|---|---|---|---|
| 1 | **Agreement**（合意） | 「はい、それでいきましょう」 | 決定文として最も安定 |
| 2 | **Resolution Restatement**（復唱） | 「じゃあ OIDC の方向で、ということで」 | 安定。照合が通りやすい |
| 3 | Resolution Proposal（提案） | 「OIDC に寄せる手もあります」 | **言い換えられ、撤回される** |
| — | Issue（論点提示） | 「認証方式どうしましょう」 | Q の引用に使う |

提案発話を DEC の `引用` に使うと、後から「それは提案にすぎなかった」という争いになる。
**合意・復唱の発話があればそれを採る。** 無ければ提案発話を採り、`信頼度` は照合結果に従う
（提案発話であることを理由に下げる必要はない）。

なお Restatement は人間の一致率が最も低く自動検出も F1 0.16 なので、取りこぼす前提でよい。

## 沈黙の扱い — 無条件で `推測`

決定権のある役割が結論を述べ、異論なく次の論点に移った場合、DEC として起票してよい。
ただし **`信頼度: 推測` を固定**で付ける。

同じく、**代替案の却下を沈黙から判定した場合も `信頼度: 推測` に固定する。**
沈黙を却下のシグナルとして使う手法は文献に対応するものがない。明示的な合意ですら人間の
一致率が κ 0.63、自動検出が F1 0.39 で最も難しいクラスである。沈黙はそれより弱い根拠でしかない。

`言及のみ` は「代替案の言及の引用は取れたが、却下理由の発言がない」場合に限って使う。

## 却下パターンの検出（3段階）

代替案の却下は次の3段階で現れる。

```
段階1  代替案の言及   「〜という手もある」「〜でもいいんだけど」「〜も考えたんですが」
                       「〜だとどうですか」「〜ってのはどうでしょう」
段階2  否定的な反応   「うーん」「それだと〜」「〜が厳しい」「〜はちょっと」／または沈黙
段階3  別案への移行   「じゃあ〇〇で」
```

### 段階1だけがあるケースの扱い（最重要）

**段階2・3がなく、代替案が言及されたまま流れた場合も必ず記録する。**

```yaml
代替案:
  - 案: 自社でID基盤を実装
    却下理由: 記録なし
    引用: 自前で作る手もあるんですけどね
    信頼度: 推測              # 沈黙を根拠にしたので 推測 固定
```

反応が「沈黙」ではなく明示的な否定発話（「それだと厳しい」等）だった場合は、その発話を
却下理由の引用にして `信頼度` は照合結果に従う。

これが最も価値の高い抽出対象である。半年後に「あの案はなぜやらなかったのか」に対して
「**そもそも検討されずに流れた**」と答えられる。議事録には100%残らず、文字起こしからしか
取れない。**絶対に捨てないこと。**

却下理由が発言として存在しない場合、**理由を推測して書いてはならない。** `記録なし` を入れる。

## 7種への振り分けの決定木

```
発言が…
├ 期限または担当が伴う約束              → ACT
├ 決定権のある役割による結論の表明       → DEC
│   └ 同じ論点で言及された代替案は DEC の中に入れる
├ 結論が出ていない／誰かの回答待ち       → Q
├ 選択肢を削る環境の性質                → DEC の却下理由に書く（CON は Pass 4）
├ 条件付きの前提（「今は」「当面」）      → DEC の `なぜ` に書く（ASM は Pass 4）
└ 上記いずれでもない                    → 何も作らない（LOG に残っていればよい）
```

**「何も作らない」を選ぶことを恐れないこと。** 1つの論点から DEC が0件でも正常である。

## 既存 Q / ACT との同一性判定

渡された既存 Q / ACT の一覧と照合する。

- 同じ問い・同じ約束が再度議論されている場合、**新規作成せず更新差分を出す**
- 判定に確信が持てない場合は**新規として起票し、`同一性候補: [Q-031]` を付けて人間に判断を
  委ねる**
- Q が解決した場合は、対応する DEC の id を `resolved_by` に入れる

同一性判定の精度は用語集の充実度に依存する。最初の数回は誤りが多い前提で、必ず候補を明示する。

## 出力形式

`schema.md` の定義に従う。新規カードは frontmatter 完備で出力する。既存カードの更新は
差分のみを次の形で出力する。

```yaml
updates:
  - id: Q-031
    status: 解決
    resolved_by: DEC-014
    最終言及: 2026-09-18

  - id: ACT-005
    status: 完了
    更新履歴_追記: "2026-09-18: 完了報告あり"
```

## `範囲` の判定（受託開発では必ず立てる）

DEC には `範囲: 当初合意内 / 範囲外(追加) / 判定保留` を必ず入れる。
`種別`（交渉可能 / 技術判断 / 契約制約）とは**直交する軸**で、「今後変えられるか」と
「当初の合意に入っていたか」は別の問いである。

- 発話に「当初の要件に入っていた／入っていない」の明示があればそれに従う
- **明示がなければ無条件で `判定保留`。推測して判定しない**
- `判定保留` の DEC には、対応する Q を自動で起票する
  （title: 「〈DEC の title〉は当初合意範囲内か」／確認先: 顧客PM）

ここで無理に判定すると、後で追加請求の根拠を失う。

## `担当` と `期限`（ACT）は空欄を許す

アクション抽出のクラス別難易度は一貫して **本文 > 担当 > 期限** の順
（Purver ほか 2007: Description 0.19 / Timeframe 0.22 / Owner 0.24、人間の一致率も
κ 0.435–0.78）。

**発話に明示されていない担当・期限は空欄にする。** 推測で埋めない。
空欄が正常な出力である。②の確認で人間が埋める。

## 自動導出するフィールド

次は `role-mapping.yaml` から機械的に決める。推測しない。

| フィールド | 導出元 |
|---|---|
| `決定の所在` | 結論を述べた役割ラベルをそのまま |
| `会議体` | 会議メタの会議体名をそのまま |
| `種別`（DEC） | その役割の `決定の種別` |
| `担当`（ACT） | その役割の `社名`（発話に明示がなければ空欄） |
| `derived_from` | 処理中の LOG カードの id |

## セグメント境界をまたぐ引用を許す

トピック分割は **Pk 0.33–0.41**、つまり境界判断の約3割が誤る（Solbiati ほか、AMI/ICSI）。
境界は数十秒ずれる前提で、隣接セグメントの LOG カードから引用してよい。その場合
`derived_from` に両方の LOG id を入れる。境界を厳格に閉じない。

`role-mapping.yaml` に無い役割ラベルの場合、決定権「なし」として扱い、出力末尾に
`# 未登録の役割: 〇〇` を付ける。

## 引用の書き方

- LOG カード本文から**文字単位で正確に**コピーする
- 前後を削るのは可。語を変えるのは不可
- 鉤括弧は付けない
- 複数の発言にまたがる引用は作らない（1発言から1引用）

引用の正確性は後段のスクリプトで機械検証され、一致しないものは `信頼度: 推測` に強制降格
される。整えて書くと降格するだけなので、原文のまま写すこと。

## 禁止事項

- 却下理由・`なぜ` を発言から推測して書く（`記録なし` / 空欄を使う）
- 制約カード（CON）・前提カード（ASM）・用語カード（TERM）を作る
- 複数論点をまとめて処理する
- 引用を整える・要約する
- 決定権のない役割の発言から DEC を起票する

## 人間の確認（②の前半・10〜15分）

出力を上から見て、次だけ触ってもらう。

1. **DEC の `なぜ` を1行書く** — ここは人間しか書けない。空欄なら空欄のままでもよいが、
   書けるなら書く
2. **`信頼度: 推測` の DEC を確認** — 正しければ `逐語あり` に上げるか、引用を足す。
   違えば Q に落とす
3. **`代替案` の `却下理由: 記録なし` を確認** — 思い出せるなら書く。思い出せないならそのまま
4. **`作らない` の3値を選ぶ** — `該当なし` / `記録なし` / 内容を記入
5. **ACT の期限を入れる** — 担当（社名）は自動で入っている
6. **`同一性候補` の判定** — 既存 Q/ACT の続きか、新規か

`なぜ` を LLM に書かせないこと。もっともらしい理由が入り、人間が「まあそんな感じ」で
通してしまう。これがこの仕組みの最大の失敗モードである。
