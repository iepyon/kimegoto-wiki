# 会議を取り込む — Pass 1〜3 を一続きで

共通規約は `CLAUDE.md` が正典。**各パスの判定基準は、そのパスのスキルにしか無い**
（`segment` / `log-cards` / `extract`）。ここには**順序と、止まる場所**だけを置く。
両方に書くと片方が古くなる。

利用者が覚えるのは「取り込んで」の一言。会議 ID も、段の順番も、どこまで済んだかも
機械が知っている（`kime status`）。

## 止まる場所は2つだけ

| どこで | なぜ |
|---|---|
| Pass 1 の直後 — **論点の粒度を人が確認する** | 10行の確認で、後の全パスの後戻りを防ぐ。飛ばすと高くつく |
| Pass 3 まで終わったあと | 確認②（`なぜ`・担当・期限・範囲・昇格・議題の締め）は人が判定する。このスキルは踏み込まない |

それ以外は人に聞かずに進む。ただし各パスの判定基準が「人間に聞く」としている箇所
（会議の場で出た議題を起票するか、未登録の役割）はそこで聞く。

## 手順

0. `python3 tools/kime.py status` を出す。**いまの会議**と、どこまで済んでいるかが出る。
   会議 ID の指定が無ければ「いまの会議」を使う。途中から再開するときも同じで、
   「次にやること」から始める（済んだ段をやり直さない）。
   文字起こしが無ければ、置き場（`meetings/MTG-YYYYMMDD/transcript.md`）を案内して止まる
1. **Pass 1** — `.claude/skills/segment/SKILL.md` を読み、そのとおりに `segments.yaml` を作る。
   **粒度の確認で止まる**（そのスキルの「人間の確認」）。返ってきた指示で直し、
   通るまで進まない
2. 確認が通ったら `python3 tools/kime.py agenda-sync --meeting MTG-YYYYMMDD --write`
   （扱った議題の書き戻し。一意に決まるので機械が書く）
3. **Pass 2** — `.claude/skills/log-cards/SKILL.md` のとおりに LOG と未知語リストを作る。
   未知語リストは見せるだけでよい（表記崩れの追記は確認②で）
4. **Pass 3** — `.claude/skills/extract/SKILL.md` のとおりに、**必ず1論点ずつ**カードを起こす
5. `python3 tools/kime.py scope-questions --meeting MTG-YYYYMMDD` で範囲の問いを見て、
   内容を確認したうえで `--write`
6. `python3 tools/kime.py verify-quotes --fix` → `python3 tools/kime.py lint` で error 0
7. `python3 tools/kime.py status` をもう一度出して締める。表の「確認②」の行が、
   人が次に判定するものの数。**「確認②を始めて」と言えば `/review` が進行する**と伝える

## 途中で止まったとき

コンテキストが切れても、`kime status` が残りを数える。「次にやること」から再開する。
LOG が途中まででも、カードが途中まででも、済んだものは飛ばされる。

## 禁止事項

- 粒度の確認を飛ばす、または自分で「確認済み」とみなす
- 確認②の項目（`なぜ`・却下理由・担当・期限・`範囲`・昇格・議題の締め）を埋める
- 各パスの判定基準をここに写す、あるいはここで上書きする
- 全論点を一度に Pass 3 へ渡す
