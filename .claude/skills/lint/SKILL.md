# 整合性の点検

共通規約は `CLAUDE.md` が正典。チェック項目の正本は `ontology.yaml` と
`tools/kimelint.py`。以下は本スキル固有の手順。

## 役割分担

`kimelint.py` が機械的に担う部分は、**スクリプトの出力をそのまま報告に転記する。**
そこを読み直して再点検しない（時間の無駄であり、機械のほうが正確）。
あなたは残りの**意味的なチェック**に集中する。

## 手順

1. `python3 tools/kime.py lint` を実行し、出力をそのまま転記する
2. 以下の意味的チェックを行う
3. 所見をまとめる。**カードは書き換えない**（検出役に徹する）

## 意味的チェック（機械にできないもの）

機械は形しか見ない。次は人と LLM にしか見えない。

1. **引用の文脈妥当性** — 引用が文字列として存在することと、それがその決定の
   根拠として妥当であることは別。無作為に3枚選んで LOG を読み、確かめる
2. **DEC / Q の振り分け** — 「決定」とされているものが本当に決定か。
   `decision-guide.md` の境界例に照らす。無作為に3枚
3. **矛盾** — 過去の決定と逆向きの決定が出ていないか。
   これは決定論 lint には入れていない（意味的判断なので）
4. **論点の粒度** — LOG 1枚から何枚もカードが出ている、あるいは
   何枚もの LOG から1枚も出ていないなら、Pass 1 の切り方を疑う

## warning の扱い

`CLAUDE.md` の「warning 0 を目指さない」に従う。
**warning が多いこと自体を問題として報告しない。**
「期限を過ぎたアクションが5件ある」は、記録の不備ではなく仕事の状態である。

## 引用不一致を見つけたら

`python3 tools/kime.py verify-quotes --fix` を提案する。
自分で LOG のほうを直さない（LOG は不変層）。
