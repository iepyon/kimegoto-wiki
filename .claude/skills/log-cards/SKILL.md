# Pass 2 — LOG カードの生成

共通規約は `CLAUDE.md` が正典。以下がこのパスの正本。

文字起こしを論点単位の LOG カードに整形する。**ここが後続すべての土台になる。**
LOG はこの会議から生まれるすべての引用の照合先であり、一度コミットしたら書き換えられない。

## 手順

1. `meetings/MTG-YYYYMMDD/segments.yaml` と `transcript.md` を読む
2. `terms/*.md` の `正式` と `表記揺れ` を全部読む（正規化に使う）
3. 下記の判定基準に従って整形する
4. `python3 tools/giji.py new log --meeting MTG-YYYYMMDD` で ID を採番する
5. `meetings/MTG-YYYYMMDD/logs/LOG-YYYYMMDD-NN.md` に書き出す
6. 未知語リストを `meetings/MTG-YYYYMMDD/unknown-terms.yaml` に出す
7. `python3 tools/giji.py lint --check log-format` で形式を確認する

## 最重要ルール

**逐語は削ってよいが、言い換えは禁止。**

| | 内容 |
|---|---|
| **許可** | フィラーの除去 — 「あー」「えーと」「なんか」「その」「まあ、その」 |
| **許可** | 言い直しの重複除去 — 「これは、これはですね」→「これはですね」 |
| **許可** | 用語集の `表記揺れ` に載っている語を `正式` に置換 |
| **許可** | 意味を持たない相槌行の削除 — 「はい」「うん」のみの発言 |
| **禁止** | 語順の変更 |
| **禁止** | 語彙の置換（用語集による正規化を除く） |
| **禁止** | 丁寧語・書き言葉への変換 |
| **禁止** | 要約・圧縮 |
| **禁止** | 複数の発言を1つにまとめること |
| **禁止** | 発言者の推測による補完 |

判断に迷ったら**削らずに残す**。残しすぎによる害はないが、改変は検証機構を壊す。

## 相槌の扱いの例外

単独では削除してよい相槌でも、**同意や否定の意思表示として機能している場合は残す**。

- 削除してよい: 説明の途中に挟まる「はい」「うん」
- 残す: 提案に対する「はい、それでいきましょう」「うーん…」
- 残す: 沈黙。`- **(沈黙 約8秒)**` として記録する

沈黙は却下のシグナルであり、Pass 3 が使う。落とさないこと。

## 出力形式

論点ごとに1ファイル。frontmatter と本文。

```markdown
---
id: LOG-20260918-03
type: log
meeting: MTG-20260918
title: 認証方式の選定
種別: 議論
時刻: "00:21:10 - 00:34:52"
参加役割: [顧客PM, 開発リーダ, 開発メンバー]
---

## 発言

- **顧客PM**: ADに繋ぐのは、まあVPNが固定IPなんで厳しいですね
- **開発リーダ**: だとするとOIDCに寄せる手もあります
- **開発リーダ**: 自前で作る手もあるんですけどね
- **(沈黙 約6秒)**
- **顧客PM**: じゃあOIDCの方向でいきましょう
- **開発メンバー**: 利用者は当面50人くらいの想定でいいですか
- **顧客PM**: はい、当面はその規模です
```

本文の行の形式は `- **役割**: 発言` で固定する。引用検証がこの形式を前提にしている。
発言内に鉤括弧を付けない（検証時の正規化で除去されるが、付けない方が読みやすい）。

## 検証可能な事実の列挙（LOG カードの第2セクション）

発言ログに加えて、そのセグメントで**確定した検証可能な事実**を列挙する。
数値・日付・固有名・件数・バージョンなど、**発話に明示的に現れたもののみ**。

```markdown
## 確定した事実

- 利用者規模：当面50人（顧客PM, 00:32:10）
- 移行対象データ：3テーブル、約12万件（開発リーダ, 00:14:02）
- IdP 確認の回答期限：10月上旬（顧客PM, 00:29:41）
```

推論・要約・補完はしない。発話に数値がなければ書かない。

**理由**：Kirstein ほか (2025) の FRAME は、要約生成の前に「自己完結した検証可能な事実」を
抽出して生成をそれに制約することで、**幻覚を 3–4/5 → 1/5、欠落も 3–4/5 → 1/5** に下げている。
このセクションは Pass 3 が参照する事実台帳になり、幻覚と欠落の両方に効く。

## 未知語の検出

次の条件を**すべて**満たす語を未知語として報告する。

1. 用語集（`terms/*.md` の `正式` と `表記揺れ` の全値）に存在しない
2. カタカナ語 / 英字略語 / 不自然な漢字列 のいずれか
3. 同一会議内で3回以上出現

一般的なビジネス用語（「スケジュール」「リソース」「アサイン」等）は除外する。
このプロジェクト固有の語、製品名、技術用語に限る。

```yaml
meeting: MTG-20260918
unknown_terms:
  - 語: オイデッシー
    出現回数: 4
    初出: LOG-20260918-03
    文脈: ADに繋ぐかオイデッシーに寄せるか
    推定: OIDC の表記崩れの可能性

  - 語: 権限マトリクス
    出現回数: 3
    初出: LOG-20260918-05
    文脈: 権限マトリクスを先に固めないと
    推定: 新規用語の可能性
```

`推定` 欄では、既存用語の表記崩れか新規用語かの見当を1行で書く。断定しない。

## 禁止事項

- 決定事項・未定事項・アクションを抽出しない（Pass 3 の仕事）
- 制約・前提を抽出しない（Pass 4 の仕事）
- 論点の分割・統合をしない（Pass 1 の結果に従う）
- 一般的なビジネス用語を未知語に含めない

## 人間の確認

未知語リストだけ見てもらう。所要1〜2分。

- **表記崩れ** → 既存の TERM カードの `表記揺れ` に追記する（次回以降の正規化に効く）
- **新規用語** → Pass 4 の昇格候補として持ち越す
- **どちらでもない** → 無視

LOG カード本体は確認不要。改変禁止ルールを守っていれば内容は原本と等価。

## 一度コミットしたら書き換えない

LOG は不変層。生成中（未コミット）は自由に直してよいが、コミットしたあとは
PreToolUse フックが書き込みを止める。
