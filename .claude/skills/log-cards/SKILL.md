# Pass 2 — LOG カードの生成

共通規約は `CLAUDE.md` が正典。以下がこのパスの判定基準。

**LOG はこの会議から生まれるすべての引用の照合先**であり、一度コミットしたら書き換え
られない（生成中＝未コミットのあいだは自由に直してよい）。

## 手順

1. `meetings/MTG-YYYYMMDD/segments.yaml` と `transcript.md` を読む
   （会議の指定が無ければ `python3 tools/kime.py status --id` のいまの会議）
2. `terms/*.md` の `正式` と `表記揺れ` を全部読む（正規化に使う）
3. `python3 tools/kime.py new log --meeting MTG-YYYYMMDD` で ID を採番する
4. `meetings/MTG-YYYYMMDD/logs/LOG-YYYYMMDD-NN.md` に書き出す
5. `python3 tools/kime.py lint --check log-format` で形式を確認する
6. `python3 tools/kime.py unknown-terms --meeting MTG-YYYYMMDD` を回し、
   出てきた候補から未知語リストを作る（下記）

## 最重要ルール — 削ってよいが、言い換えは禁止

| | 内容 |
|---|---|
| **許可** | フィラーの除去 — 「あー」「えーと」「なんか」「その」 |
| **許可** | 言い直しの重複除去 — 「これは、これはですね」→「これはですね」 |
| **許可** | 用語集の `表記揺れ` に載っている語を `正式` に置換 |
| **許可** | 意味を持たない相槌行の削除 — 「はい」「うん」のみの発言 |
| **禁止** | 語順の変更／語彙の置換（用語集による正規化を除く） |
| **禁止** | 丁寧語・書き言葉への変換／要約・圧縮 |
| **禁止** | 複数の発言を1つにまとめる／発言者の推測による補完 |

迷ったら**削らずに残す**。残しすぎによる害はないが、改変は検証機構を壊す。

相槌の例外 — **同意や否定の意思表示として機能している場合は残す。**

- 削除してよい: 説明の途中に挟まる「はい」「うん」
- 残す: 提案に対する「はい、それでいきましょう」「うーん…」
- 残す: 沈黙。`- **(沈黙 約8秒)**` として記録する。**沈黙は却下のシグナルで、Pass 3 が使う**

## 出力形式

論点ごとに1ファイル。

```markdown
---
id: LOG-20260918-03
type: log
meeting: MTG-20260918
title: 認証方式の選定
種別: 議論
時刻: "00:21:10 - 00:34:52"
参加役割: [顧客PM, 開発リーダ, 開発メンバー]
---

## 発言

- **顧客PM**: ADに繋ぐのは、まあVPNが固定IPなんで厳しいですね
- **開発リーダ**: 自前で作る手もあるんですけどね
- **(沈黙 約6秒)**
- **顧客PM**: じゃあOIDCの方向でいきましょう

## 確定した事実

- 利用者規模：当面50人（顧客PM, 00:32:10）
- 移行対象データ：3テーブル、約12万件（開発リーダ, 00:14:02）
```

本文の行は `- **役割**: 発言` で固定する（引用検証がこの形式を前提にしている）。
発言内に鉤括弧を付けない。

## 確定した事実

そのセグメントで**確定した検証可能な事実**を列挙する。数値・日付・固有名・件数・
バージョンなど、**発話に明示的に現れたもののみ**。推論・要約・補完はしない。
発話に数値がなければ書かない。

このセクションが Pass 3 の参照する事実台帳になり、幻覚と欠落の両方に効く
（根拠は `research-notes.md`）。

## 未知語の検出

**候補拾いは機械がやる。** `kime unknown-terms` が、用語集に無い / 規定の回数以上
出現する / カタカナ・英字・漢字列のいずれか、の3条件を満たす語を出現回数つきで出す。
**自分で数えない**（回数はいちばん間違えるところで、間違えると閾値の判定ごと狂う）。

出てきた候補に対して、あなたがやることは2つだけ。

1. **一般的なビジネス用語を落とす** — 「スケジュール」「リソース」「アサイン」
   「サーバー」「フォルダ」等。このプロジェクト固有の語・製品名・技術用語だけを残す
2. **`推定` を1行書く** — 既存用語の表記崩れか、新規用語か。**断定しない**

残ったものを `meetings/MTG-YYYYMMDD/unknown-terms.yaml` に書く。

```yaml
meeting: MTG-20260918
unknown_terms:
  - 語: オイデッシー
    出現回数: 4
    初出: LOG-20260918-03
    文脈: ADに繋ぐかオイデッシーに寄せるか
    推定: OIDC の表記崩れの可能性
```

`語` / `出現回数` / `初出` / `文脈` はコマンドの出力をそのまま写す。書き換えない。

## 禁止事項

- 決定事項・未定事項・アクションを抽出する（Pass 3 の仕事）
- 制約・前提を抽出する（Pass 4 の仕事）
- 論点の分割・統合をする（Pass 1 の結果に従う）
- 一般的なビジネス用語を未知語に含める

## 人間に見てもらうのは未知語リストだけ（1〜2分）

- **表記崩れ** → 既存 TERM の `表記揺れ` に追記（次回以降の正規化に効く）
- **新規用語** → Pass 4 の昇格候補として持ち越す

LOG カード本体は確認不要。改変禁止ルールを守っていれば内容は原本と等価。
