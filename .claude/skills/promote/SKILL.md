# Pass 4 — 昇格候補の提示

共通規約は `CLAUDE.md` が正典。判定基準の正本は `decision-guide.md` の
「昇格の門」、手順の正本は `prompts/pass4_promote.md`。以下は本スキル固有の手順。

## 手順

1. `python3 tools/giji.py promote-input --meeting MTG-YYYYMMDD` で材料を組み立てる
2. `prompts/pass4_promote.md` の指示をそのまま実行する
3. `meetings/MTG-YYYYMMDD/promote-candidates.yaml` に候補を書き出す
4. **人間の yes/no を待つ。承認されたものだけをカードにする**

## 入力の時点で門が閉じている

`giji promote-input` は **`なぜ` が未記入の決定を材料から落とす。**
プロンプトの注意書きではなく、入力の欠落で守っている。
落とされた決定は出力の末尾に一覧で出るので、人間に伝える。

理由の書かれていない決定から制約が生まれると、将来の議論でその制約だけが効く。

## 出す問いは4種類だけ

新規制約 / 既存制約への紐づけ / 新規前提 / 用語（新規・表記揺れの追記）。
「この決定は見直すべき」のような意見は書かない。

## 門

- **CON**: その決定に固有か、環境の性質か。固有なら昇格しない。
  **迷ったら昇格させない**（同じ理由が2つ目の決定に現れた時点で昇格すればよい）
- **ASM**: `脆弱性: 高` かつ `崩れたら見直す決定` が特定できるものだけ。
  逆リンクのない前提カードは飾りになる。候補にも出さない

## このパスでやらないこと

- カードファイルを作成・更新する（承認後に別途行う）
- `硬度` を自分で決める（`種類` × `所在` から機械的に決まる。lint が照合する）
- `失効条件` を推測で埋める（`property` なら `該当なし`、手掛かりが無ければ `不明`）
