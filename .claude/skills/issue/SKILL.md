# GitHub Issue の下書き

共通規約は `CLAUDE.md` が正典。以下は本スキル固有の手順。

## 手順

1. `python3 tools/kime.py issue --act ACT-NNN` で本文を出す（**この時点では起票しない**）
2. 本文を人間に見せる
3. 起票してよいか、どのリポジトリに出すかを確認する
4. 承認を得てから `--repo owner/repo --create` を付けて実行する

## 起票の前に必ず確認する

外部サービスへの書き込みであり、取り消しづらい。
本文とリポジトリを提示し、明示的な承認を得てから実行する。
「全部起票しますか」ではなく、1件ずつ確認する。

## すべての ACT を起票しない

ACT は**会社間の約束**の記録で、Issue は自社のタスク管理。粒度も寿命も違う。
全件を自動起票すると Issue のほうが壊れる。どれを起票するかは人間が選ぶ。

## 二重起票は機械が防ぐ

起票済みの ACT は `issue` フィールドを持ち、再実行時に飛ばされる。
このフィールドを手で消さない。

## ACT の内容を変えない

Issue の本文を整えるのはよいが、それに合わせて ACT カードを書き換えない。
ACT は会議で言われたことの記録であって、タスクの仕様書ではない。
