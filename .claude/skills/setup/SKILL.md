# セットアップ — 最初に一度だけ

共通規約は `CLAUDE.md` が正典。門を立てて案件を指す作業は `tools/setup.sh` が持つ。
このスキルは**その呼び出しと、人が決めることの聞き取り**だけを持つ。

## 手順

1. `AskUserQuestion` で**どの案件で始めるか**を聞く。選択肢は `projects/` にある既存の案件
   （同梱のデモ `demo-kb` など）と「新しい案件を作る」。新しい案件なら、ディレクトリ名
   （案件名）も聞く
2. 新しい案件なら、雛形をコピーする: `cp -r templates/project projects/<案件名>`。
   既に同名のディレクトリがあればコピーせず、止まって聞く
3. `sh tools/setup.sh <案件名>` を実行する。門を立て、`.env` を書き、門を一度通す。
   **通らなければ出力をそのまま見せて止まる**（門を迂回しない、`--no-verify` を勧めない）
4. 既存の案件ならここで終わり。6 へ
5. 新しい案件なら、`projects/<案件名>/role-mapping.yaml` を埋める（下の「role-mapping を埋める」）
6. `python3 tools/kime.py status` を出して締める。新しい案件なら、あわせて次の2つを伝える
   - `decision-guide.md` をチームで読み、境界例をすり合わせる
     （このスキルは読み合わせを代行しない）
   - 次の一歩は「次回のアジェンダを出して」（`/agenda`）か、文字起こしを置いて
     「会議を取り込んで」（`/ingest`）

## role-mapping を埋める

このファイルが Pass 3 の解釈と ACT の担当社名を決める。**決定権を推測で書くと、嘘の DEC が
起票される**ので、書くのは人が言ったことだけ。フィールドと語彙は雛形のコメントが正本。

1. `AskUserQuestion` で `meta` を聞く: 案件名・自社名・顧客の社名・協力会社・会議体名（契約上の名前）
2. 話者分離が出力する**役割ラベル**を聞く。雛形にある役割を選択肢に出し、足りない役割は
   「Other」で足してもらう。表記は文字起こしに出る形に揃える（言い換えない）
3. 役割ごとに `所属` と `決定権`、決定権がありなら `決定の種別` を聞く。雛形の値を既定の
   選択肢にしてよいが、**選んでもらうまで書かない**。聞いても決まらない役割は `決定権: なし`
   にしてその旨を伝える（迷ったら Q に落とす、と同じ向き）
4. 使わない役割は消し、`社名` は `meta` から写す（一意に決まるので聞き直さない）
5. `python3 tools/kime.py lint --root projects/<案件名>` で error 0 を確かめる

## 禁止事項

- 決定権・決定の種別・会議体名を、案件の説明や一般論から推測して埋める
- `decision-guide.md` を要約して「読んだこと」にする、または書き換える
- 門が通らないのを、検査を外して（`.wip` を置く、フックを外す）通したことにする
- `tools/setup.sh` の手順をここに写して手で打つ
