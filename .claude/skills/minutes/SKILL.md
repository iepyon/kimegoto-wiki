# カードから読み物を出す

共通規約は `CLAUDE.md` が正典。以下がこのパスの判定基準。

議事録も次回アジェンダも**カードの射影**で、どちらも同じ性質を持つ。

- **内容の追加・推測は一切しない。** 材料に無いことを書かない
- **ファイルには保存しない。** 会話の中に出す

保存すると、カードを更新したときに古くなり二重管理が復活する。
「最終議事録」は固定物ではなくリーダ承認時点のスナップショットで、顧客提出が必要なら
その時点で人間が PDF 等に出力する。渡した後にカードが更新されても正常な状態。

## 議事録

### 手順

1. `python3 tools/giji.py minutes-input --meeting MTG-YYYYMMDD [--edition customer]`
2. **材料の末尾に出る「議事録の骨格」の見出しを、その順で使って書く**
3. 会話の中に出す

節構成は版ごとに違い、正本は `ontology.yaml` の `editions`。CLI が骨格として出すので、
**ここに節の一覧を持たない**（持つと版を足したときに必ず片方が古くなる）。

### 守ること

1. **カードに書かれていないことを書かない。** 空欄は空欄として扱う
2. `なぜ` が空欄の決定は、決定内容だけを書く。理由を補完しない
3. `却下理由: 記録なし` は、社内版では **記録なし** と太字で明記する
4. 逐語引用は材料から正確に写す
5. 前回から引き継がれた ACT を必ず冒頭に置く（定例で最初に確認される項目）
6. 版の指定に従う。指定がなければ社内版

社内版では **`記録なし` と `推測` を隠さない。** 言語化されなかった量が見えることに
価値がある。末尾の「記録の状態」がこの会議の記録品質を可視化する。
逐語引用を1つは入れる（判断の空気が残る）。

### 禁止事項

- カードにない決定・理由・アクションを書く
- 空欄を「特になし」で埋める（`未記入` と `該当なし` は別の意味）
- 顧客提出版に役割ラベル・カード ID・逐語引用を残す
- 材料の脚注にある「機械的に落としたもの」の件数を本文に混ぜる
- 議事録をファイルとして保存する
- カードを更新する（レンダリングは読み取り専用）

### 顧客提出版 — 出せない情報は CLI が落としている

`--edition customer` の材料は、`信頼度: 推測` の決定、`却下理由: 記録なし` の代替案、
内部メタとカード ID、自社側の制約、LOG 本文と逐語引用が**すべて除外済み**。
除外規則は `ontology.yaml` の `editions.customer` にあり、CLI がそれを実行する。

**渡された材料に無いものは、出してはいけないもの。**
漏れたら契約上の事故になるので、この判定を LLM の遵守に賭けていない。

**顧客側の制約（所在=顧客側）は出してよい。** 顧客自身の事情であり、合意の前提として
明記しておく方が後の齟齬を防ぐ。

### 顧客提出版でのあなたの仕事は表記の変換だけ

- 役割 → 社名（材料の側で変換済み）
- 「却下」→「採用しなかった」／「作らない」→「本フェーズの対象外」
- 未確定のものは断定せず `確認事項` に移す
- 末尾のみなし確定の一文を、材料に書かれたとおり定型で入れる
- 会議体名を冒頭に書く（決定の重みは会議の位置づけで変わる。役割だけでは契約上の
  会議体定義と接続できない）

みなし確定は、相手方が確認していない記録が「自己に都合の良いことしか書かれていない」
メモとして扱われるのを防ぐための定型。異議なく確定したら、その日を各 DEC の `確定日` に
書き戻す（`giji confirm --meeting MTG-... --sent YYYY-MM-DD`）
— これが25分の運用に足す唯一の追加作業。

## 次回アジェンダ

### 手順

1. `python3 tools/giji.py agenda` を実行する
2. 会議で読み上げられる形に整えて提示する

### 順序を変えない

冒頭は **`なぜ` が未記入の決定**。これは書式の都合ではなく、
「書かないことに付けたコスト」そのもの。
未記入のあいだ、その決定は制約・前提へ昇格できない。
順序を変えると、このコストが効かなくなる。

その後は 未完了アクション → 未決の問い → （四半期なら）前提の棚卸し。

### 四半期の棚卸し

年4回。`脆弱性: 高` の前提だけを、signpost に照らして「崩れたか」だけ見る。5分で済ませる。
全件を追跡しない（2週25分の運用では破綻する）。進行は `/review` が持つ。

### このビューが読まれないなら

引かれない記録は死んでいる。アジェンダが定例の冒頭で読まれていないなら、
それ自体が「この仕組みが定着していない」という所見。カードを増やしても直らない。
