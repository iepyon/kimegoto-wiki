# 議事録のレンダリング

共通規約は `CLAUDE.md` が正典。以下がこのパスの判定基準。

カード群から議事録をレンダリングする。**内容の追加・推測は一切しない。**

## 手順

1. `python3 tools/giji.py minutes-input --meeting MTG-YYYYMMDD [--edition customer]`
2. 返ってきた材料だけを使い、下記の節構成で書く
3. **会話の中に出す。ファイルには保存しない**

保存すると、カードを更新したときに議事録が古くなり二重管理が復活する。
「最終議事録」は固定物ではなくリーダ承認時点のスナップショットで、顧客提出が必要なら
その時点で人間が PDF 等に出力する。渡した後にカードが更新されても正常な状態。

## 守ること

1. **カードに書かれていないことを書かない。** 空欄は空欄として扱う
2. `なぜ` が空欄の決定は、決定内容だけを書く。理由を補完しない
3. `却下理由: 記録なし` は、社内版では **記録なし** と太字で明記する
4. 逐語引用は材料から正確に写す
5. 前回から引き継がれた ACT を必ず冒頭に置く（定例で最初に確認される項目）
6. 版の指定に従う。指定がなければ社内版

## 禁止事項

- カードにない決定・理由・アクションを書く
- 空欄を「特になし」で埋める（`未記入` と `該当なし` は別の意味）
- 顧客提出版に役割ラベル・カード ID・逐語引用を残す
- 材料の脚注にある「機械的に落としたもの」の件数を本文に混ぜる
- 議事録をファイルとして保存する
- カードを更新する（レンダリングは読み取り専用）

## 社内版の節構成

冒頭に 日時 / 参加役割 / 生成元（会議 ID と LOG 枚数）。以下この順に。

1. **前回アクションの結果** — ID・内容・担当・期限・状況の表
2. **決定事項** — 決定ごとに `### DEC-NNN タイトル`。決定の所在（種別）、なぜ、作らない、
   検討した代替案の表（案・却下理由・根拠）、逐語引用を1つ
3. **未決事項** — ID・内容・確認先・初出の表
4. **今回のアクション** — ID・内容・担当・期限の表
5. **新たに記録した制約・前提** — CON は（所在・硬度／失効条件）、ASM は（崩れたら見直す決定）を併記
6. **議論の経緯** — LOG カード本文を `<details>` で畳む
7. **記録の状態** — 信頼度「推測」の件数、`却下理由: 記録なし` の件数、未登録の役割ラベル

要点:

- **`記録なし` と `推測` を隠さない。** 言語化されなかった量が見えることに価値がある
- 末尾の「記録の状態」で、この会議の記録品質を可視化する
- 逐語引用を1つは入れる（判断の空気が残る）

## 顧客提出版の節構成

冒頭に 日時 / **会議体** / 出席（社名）。以下この順に。

1. **前回アクションの結果** — 内容・担当・期限・状況（ID は出さない）
2. **決定事項** — `### タイトル`（ID なし）。決定内容と合意した理由、
   「本件で検討し、採用しなかった方式」の表（案・採用しなかった理由）
3. **確認事項** — 内容・確認先・期限
4. **アクション** — 内容・担当・期限
5. 末尾にみなし確定の一文

### 出せない情報は CLI が落としている

`--edition customer` の材料は、次がすべて除外済み。除外規則は `ontology.yaml` の
`editions.customer` にあり、CLI がそれを実行する。
**渡された材料に無いものは、出してはいけないもの。**

| 出さない | 理由 |
|---|---|
| `信頼度: 推測` の決定 | 未確認のものを合意事項として提示できない。`確認事項` に回す |
| `却下理由: 記録なし` / `信頼度: 言及のみ` の代替案 | 記録の不備を対外文書に書けない。行ごと省く |
| 硬度・所在・信頼度などの内部メタ、カード ID | 内部管理情報 |
| 自社側の制約 CON（所在=自社側） | 自社の都合を対外に開示しない |
| LOG 本文・逐語引用、「記録の状態」 | 発言録と内部品質情報は出さない |

**顧客側の制約（所在=顧客側）は出してよい。** 顧客自身の事情であり、合意の前提として
明記しておく方が後の齟齬を防ぐ。

漏れたら契約上の事故になるので、この判定を LLM の遵守に賭けていない。

### あなたの仕事は表記の変換だけ

- 役割 → 社名（材料の側で変換済み）
- 「却下」→「採用しなかった」／「作らない」→「本フェーズの対象外」
- 断定を避ける箇所は残さない（未確定のものは `確認事項` に移す）
- 末尾のみなし確定の一文を、材料に書かれたとおり定型で入れる
- 会議体名を冒頭に書く（決定の重みは会議の位置づけで変わる。役割だけでは契約上の
  会議体定義と接続できない）

みなし確定は、相手方が確認していない記録が「自己に都合の良いことしか書かれていない」
メモとして扱われるのを防ぐための定型。異議なく確定したら、その日を各 DEC の `確定日` に
書き戻す — これが25分の運用に足す唯一の追加作業。
