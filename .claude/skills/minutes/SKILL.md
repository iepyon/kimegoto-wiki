# 議事録のレンダリング

共通規約は `CLAUDE.md` が正典。書式の正本は `prompts/render_minutes.md`。
以下は本スキル固有の手順。

## 手順

1. `python3 tools/giji.py minutes-input --meeting MTG-YYYYMMDD [--edition customer]`
2. `prompts/render_minutes.md` を読む
3. 返ってきた材料だけを使って日本語の議事録を書き、**会話の中に出す**

## ファイルに保存しない

保存すると、カードを更新したときに議事録が古くなり、二重管理が復活する。
カードが唯一の真実で、議事録はその射影。

「最終議事録」は固定物ではなく、リーダ承認時点のスナップショット。
顧客提出が必要なら、その時点で人間が PDF 等に出力して渡す。
渡した後にカードが更新されても正常な状態。

## 顧客提出版で落とすものは機械が落としている

`--edition customer` は、出せない情報を **CLI 側で機械的に除外済み**。
除外規則は `ontology.yaml` の `editions.customer` にある。
つまり **渡された材料に無いものは、出してはいけないもの。**

あなたの仕事は残った情報の文章化だけ。表現の変換だけを行う:

- 役割 → 社名（材料の側で変換済み）
- 「却下」→「採用しなかった」
- 「作らない」→「本フェーズの対象外」
- 未確定のものは断定せず `確認事項` に移す

末尾のみなし確定の一文は、材料に書かれたとおりに必ず入れる。

## 書かないこと

- 材料に無いこと（空欄は空欄として扱う）
- `なぜ` が空欄の決定の理由を補完すること
- 材料の脚注にある「機械的に落としたもの」の件数を本文に混ぜること
