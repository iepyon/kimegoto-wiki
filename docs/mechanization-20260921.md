# スキルから道具へ移した記録（2026-09-21）

`docs/backlog.md` が「やらないと決めたこと」、`docs/dryrun-20260918.md` が「通した記録」。
これは**境界を引き直した記録**。何をスキル（LLM）から道具（CLI）へ移し、何を移さないと
決めたかを1枚にする。

## 動機

`ontology.yaml` には `derivations`（`種類` × `所在` → `硬度`、役割 → `種別`）が最初から
あったが、**適用するコードが無く、lint が事後照合するだけ**だった。つまり値そのものは
LLM が書いていて、食い違いを直すのは人間の仕事になっていた。

一意に決まる写像を LLM にやらせると、ときどき静かに間違う。機械が書けば最初から合う。
**機械が書き、lint は保険として残す。**

## 移したもの（7件）

| # | 移したもの | 移した先 | 効いた理由 |
|---|---|---|---|
| 1 | 導出フィールドの記入（`決定の所在` / `種別` / `会議体` / `担当` / `所在` / `硬度` / `derived_from` / 日付） | `giji new --from-log --role [--kind]` | `derivations` が宣言されているのに適用されていなかった。あわせて「未登録の役割」「決定権なし」の注意もコマンドが出す |
| 2 | 範囲判定 Q の定型起票 | `giji scope-questions [--write]` | 条件（`判定保留` かつ `種別` が交渉可能／契約制約）も題名も確認先も一意。二重起票の検出は題名の完全一致→接尾辞＋同一 LOG の順で見る |
| 3 | 未知語の検出と**出現回数の計数** | `giji unknown-terms` | 計数は LLM がいちばん間違える。間違えると閾値の判定ごと狂う |
| 4 | segments.yaml の形式検査 | `giji lint --check segment-format,segment-count,segment-role` | スキルの禁止事項として自制に賭けていた。未登録の役割を Pass 1 の時点で出せるようになった（従来は LOG まで進んでから `role-unknown` で気づいていた） |
| 5 | 前提のトリガー語の走査 | `giji promote-input`（語リストは `ontology.yaml` の `assumption-trigger-words`） | 語リストが**スキルにしか無く**、「語彙をスキルに書かない」という規約に違反していた |
| 6 | 昇格候補の上限 | `giji promote-input` が材料に書く | 数える仕事 |
| 7 | 議事録の節構成 | `giji minutes-input` が骨格を出す（正本は `editions.<版>.sections`） | 散文でスキルに持たせると、版を足したときに必ず片方が古くなる |

## 移さないと決めたもの

機械にできないので、境界として明記しておく。

| 残したもの | 理由 |
|---|---|
| 「1論点ずつ処理する」 | 手順の制約であってコードにできない |
| lint スキルの意味的チェック4種（引用の文脈妥当性・DEC/Q の振り分け・矛盾・粒度） | 意味的判断。決定論 lint に入れると誤検出で信頼を失う（`backlog.md` と同じ判断） |
| 沈黙の解釈、却下パターンの検出 | 文献に対応する手法が無い。`信頼度: 推測` 固定で逃がす |
| 未知語から一般ビジネス語を落とす判断、`推定` の1行 | 語彙の知識が要る |
| `なぜ` / 却下理由 / 昇格の可否 / `範囲` の判定 | `CLAUDE.md` のルール1。**これを機械化したら仕組みそのものが壊れる** |

## スキルの統合（9 → 7）

| 統合 | 理由 |
|---|---|
| `promote` → `review` | Pass 4 は②の 2-2 と 2-4 に挟まれる工程。「2-2 より前に回すと材料が空になる」という順序の罠が2ファイルにまたがっていた。1つにすれば順序がずれない |
| `agenda` → `minutes` | どちらも「カードから読み取り専用で読み物を出す」。保存しない・推測しないという性質も同じ |

`segment` / `log-cards` / `extract` / `lint` / `issue` は独立のまま。
Pass 1→2 のあいだの人間のゲート（粒度の確認）と、`issue` の外部書き込み前の確認は、
別のスキルに分かれていること自体が安全装置になっている。

## 数字

```
スキル        9ファイル 958行  →  7ファイル 892行
テスト        327件            →  387件
lint          demo-kb error 0 / warning 34 → error 0 / warning 35
```

warning が1件増えたのは `segment-role`（`インフラ担当` が未登録）が Pass 1 の側で
鳴るようになったため。同じ未達を、より早い段階で映すようになった。

行数がさほど減っていないのは、消した表の代わりに「なぜ機械に任せるのか」を書いたため。
**削減の本体は行数ではなく、LLM が間違えうる箇所の数。**
