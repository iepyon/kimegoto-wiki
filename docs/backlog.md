# やらないと決めたこと

「やっていない」と「やらないと決めた」は違う。後者を残しておかないと、
同じ議論を半年ごとに繰り返す。

---

## 方針確定・不採用

### warning 0 を目指さない

`act-overdue`、`q-stale`、`why-missing`、`asm-review-due` は**真の未達を映す計器**で
あって、消すものではない。「期限を過ぎたアクションが5件ある」は記録の不備ではなく
仕事の状態である。warning を消すためにカードを書き換えるのは本末転倒。

**error 0 だけを不変条件とし、warning は計器として読む。**

### 昇格の門を lint では守れない

`kime promote-input` が `なぜ` 未記入の決定を入力から落とすことで門を閉じている。
lint 側で事後に門の破れを検出しようとしたが、**判定の根拠が無い**ことが分かった。
カードには「どの決定から昇格したか」が残らず（残るのは `derived_from` の LOG だけ）、
`影響する決定` / `崩れたら見直す決定` は昇格元ではなく影響先を指すため。

`promote-gate` は warning に落とし、意味を「紐づく決定がすべて理由未記入 ＝
この制約は理由を辿れない」に変えた。門そのものは入力の欠落で守る。

### `なぜ` を必須フィールドにしない

必須にすると人間が作話する。空欄のまま残せることが、この設計の要。
代わりに、書かないことに即時のコストを付ける（次回アジェンダへの掲示、
昇格候補から外れる）。

### ビューの鮮度を「今日時点で最新か」では見ない

`kime views --check` は当初、今日の日付で作り直して既存ファイルと比べていた。
ビューのヘッダには生成基準日が入り、`agenda-next` の期限超過も今日を基準に数えるので、
**何もコミットしていなくても日付が変わるだけで「古い」と出る。** pre-commit は
その日最初のコミットで必ず落ち、CI では恒久的に落ちる。

`--check` が見たい不変条件は「カードと突き合わせて中身が合っているか」であって
「今日時点で最新か」ではない。既存ファイルの生成基準日を読み戻し、**その日を基準に
作り直して比べる**ことにした（`--today` を明示したときは従来どおりその日で比べる）。

期限超過が増えたことはビューの誤りではなく仕事の状態である、という
「warning 0 を目指さない」と同じ判断。

### 門を CI に写さない

`.githooks/pre-commit` は `--no-verify` で迂回でき、そもそも
`git config core.hooksPath .githooks` を実行していない環境には立っていない。
だから CI を置くが、**門の中身を workflow に書き写さない。**
`sh .githooks/pre-commit --all` を呼ぶだけにする。

2箇所に書くと片方だけ直されて静かにずれる。ずれた CI は「通っているのに守られて
いない」状態を作り、フックより悪い。

### 引用一致率を品質指標にしない

AutoMin 2025 の主催者は、同一システムに対する BART-F1 が 2023年と2025年の計算で
**負の相関**を示したと報告している。自動指標を品質指標に昇格させると同じ罠に落ちる。
引用一致率はグラウンディングの健全性チェックであって、議事録の品質指標ではない。
`views/metrics.md` にはこの注記つきでしか置かない。

### `transcript.md` を引用の照合先にしない

Pass 2 で正規化しているため、原本とは文字列が一致しない。照合先は LOG カード。
原本は保管と監査のためだけに存在する。

### プロジェクト接頭辞を ID に付けない

hypothesis-wiki は Obsidian vault 全体の一意性のために `SELF-H-001` のような
接頭辞を使っているが、こちらは `schema.md` が `DEC-014` 形式を規定しており、
1案件1ディレクトリなので衝突しない。付けると設計変更になる。

### スコープの問いを Q カードにしない

`スコープ: 判定保留` という決定の状態が、そのまま「まだ顧客に聞いていない」を表す。
これを Q カードに写すと、同じ事実が2枚（決定の `スコープ` と Q の `status`）に書かれ、
閉じ忘れの lint・`resolved_by` の流用・題名から元の決定を推定する照合が要った
（`docs/dryrun-20260923.md` の 2・10）。2回の通し実験で Q の半分がスコープの問いだった。
射影にすれば、人が `スコープ` を書いた時点で消える。文面と確認先は `ontology.yaml` の
`scope-question` のまま、`kime scope-questions` が一覧し、アジェンダ・議事録が同じ写像で出す。

### 決定の側に制約・前提へのリンクを書かない

DEC の `制約` / `前提` と、CON の `影響する決定` / ASM の `崩れたら見直す決定` を両方持ち、
lint で一致を見ていた。議題では「子が親を指し、親は子の一覧を持たない」と決めたのに、
ここだけ両方向だった。ストック側は昇格の時点で人が「どの決定に効くか」を承認して書くので
そちらを正本にし、DEC 側は逆引き（`wiki.constraints_of` / `assumptions_of`）にした。

### カードに `meeting` フィールドを持たせない

カードと会議は**多対多**（同じ論点が複数の会議にまたがっても1枚のカードが
更新されていく）。単一フィールドに持たせると2回目の更新で嘘になる。
`derived_from` の LOG を辿って得る。

### 矛盾検出を決定論 lint に入れない

「過去の決定と逆向きの決定」は意味的判断。`/lint` スキル（LLM）の仕事にする。
機械で無理に判定すると、誤検出で信頼を失う。

### 承認ワークフローを作らない

リーダのレビューを必須にするとリーダがボトルネックになり、3週間で止まる。
矛盾検出が効き始めてから足す。

## 実装していないもの（意図的）

| やらないこと | 理由 |
|---|---|
| 音声 → 文字起こし | 入力は文字起こし済みテキストに限る。話者分離も外部の仕事 |
| OpenSpec 連携の実装 | 第2次。規約だけ `docs/openspec-bridge.md` に残す |
| カード同一性の自動判定 | 「これは Q-031 の続き」の判定は、用語集が育つまで精度が出ない。最初の3回は人間が指定する前提 |
| 議事録のファイル保存・PDF 化 | 保存すると二重管理が復活する。PDF はブラウザの印刷でよい |
| Web UI / 静的サイト生成 | 対象が1チーム・2週に1回。顧客情報も含む。Markdown を直接読めば足りる |
| Jira / Backlog 連携 | GitHub Issue のみ |
| PyYAML など外部依存 | 標準ライブラリ縛り。`tools/miniyaml.py` の範囲外の YAML は書かない規約にする |
| フックの自動テスト | 対話環境に依存する。フックが呼ぶ CLI 側を完全にテストし、フック自体は薄いラッパに保つ |

## 保留（判断材料が足りない）

### `asm-signpost-vague` の判定精度

「事象または閾値か」を機械で見るのは原理的に無理。否定リスト（`ontology.yaml` の
`signpost-vague-words`）にとどめ、error にはしない。運用しながら語を足す。

### 日本語の曖昧表現の扱い

「一旦置いといて」「持ち帰ります」「前向きに検討」は、日本語の業務会議ベンチマークが
存在しないため自前で決めるしかない。`deferral-phrases` に暫定で置いてあるが、
最初の3〜5会議はデータ収集フェーズと位置づける。

### `expectation × 契約` の硬度

`schema.md` の導出表がこの組み合わせを定めていない。推測で埋めず、未定義のまま
残した。lint は「導出表にない組み合わせ」として warning を出す。
実際にこの組み合わせが出てきてから決める。

語彙 `溶液` もどの組み合わせからも導出されない（語彙にはあるが未使用）。
同じく、実際に必要になってから決める。

### ~~`scope-pending-q` の判定根拠~~（解消・2026-09-23）

スコープの問いを Q カードにするのをやめ、DEC の `スコープ: 判定保留` の射影にした
（`docs/structure-20260923.md`）。DEC → Q の照合そのものが無くなったので、この保留は消えた。
