`DEC-001` が複数あり、`[[DEC-001]]` が曖昧になるため。リポジトリのルートを vault にすると
リンクをパス付きで出す必要があり、ビューの表がそのぶん読みにくくなる。

## いま何もしなくても動くこと

- カードは frontmatter + Markdown なので、そのまま開ける。frontmatter は Properties に出る
- `ID = ファイル名` なので、Obsidian 側で `[[DEC-001]]` と書けば正しいカードに解決する
- `.obsidian/` は `.gitignore` 済み（パターンが深さを問わないので `projects/<slug>/.obsidian/` も対象）
- 本文の HTML コメント（記入の注意書き）は閲覧モードで隠れる

## まだ動かないこと（B を入れるまで）

- **カードの参照がリンクにならない。** `議題: AGD-001` / `derived_from: [LOG-...]` は素の文字列で、
  Obsidian はリンクと見なさない。カード同士のバックリンク・グラフ・クリックでの移動は効かない

## 案

### A. ビューだけリンクにする（小）

`gen_views.py` が ID を `[[DEC-001]]` で出す。カードの書式は変えない。

- 効くもの: ビュー（`open-items` / `agenda-next` / `index`）からカードへ飛べる。
  各カードのバックリンク欄に「どのビューに載っているか」が出る
- 効かないもの: カード同士のバックリンクとグラフ（グラフはビューを中心にした星形になる）
- 触る範囲: `gen_views.py`、`test_gen_views.py`、全案件の `views/*.md` 再生成
- 注意:
  - `MTG-...` はファイルではなくディレクトリなのでリンクにしない（または
    `[[meetings/MTG-…/transcript\|MTG-…]]` と表中で `|` をエスケープして出す）
  - GitHub 上では `[[ ]]` が素の文字として見える。ビューを GitHub で読む人には少し読みにくくなる

### B. カードの参照フィールドもリンクにする（大）

`ontology.yaml` で参照（ref / ref-list）と宣言されたフィールドを `"[[AGD-001]]"` の形で書く。

- 効くもの: バックリンクとグラフ。DEC → LOG（根拠）、DEC/Q/ACT → AGD（議題）、
  CON/ASM → DEC（影響先）が線になる。CLAUDE.md の「リンクは片方向」はそのまま保たれ、
  逆方向は Obsidian のバックリンクがちょうど `wiki.children_of` などの逆引きの役をする
- 触る範囲:
  - 読み: `cards.py` で参照値の `[[ ]]` を剥がして正規化する。`wiki.*` と lint の参照検査は
    素の ID のまま動くので手を入れずに済む
  - 書き: `kime new`、`agenda-sync`、`update_cmd` など参照を書く道具。`cards._scalar` は
    `[` 始まりを既にクォートするので、YAML としては壊れない
  - 移行: 記録層のカード（3案件で 97 枚）を一度だけ機械で書き換える
  - `templates/card/*.md`、`schema.md` の例、スキルの記述例（`extract` / `review`）
- 制約:
  - **LOG は書き換えられない（不変層）。** 既存 58 枚の LOG の `meeting: MTG-…` は素のまま残る。
    MTG はファイルではないので、そもそもリンク先が無い。LOG の参照はリンク化の対象外にする
  - 読みが両方の書式を受けるので、書式が混ざっても動作は変わらない。揃えたいなら lint に
    warning を足す（error にはしない。動作に影響しないものを不変条件にしない）
  - 議事録・アジェンダは顧客に送るので、出力に `[[ ]]` を漏らさない。`bundle.py` は
    正規化済みの値を読むので、読みで剥がせば自然に守られる

### C. 共有の Obsidian 設定を置く（任意）

`.obsidian/` を gitignore している方針（個人設定を持ち込まない）は変えず、
`templates/obsidian/` に置いたものを `sh tools/setup.sh <案件名>` が
`projects/<案件名>/.obsidian/` へ写す。既に `.obsidian/` があれば触らない。

置く設定は事故防止のものに限る（いまは下表の1行目だけ）。

| 設定 | 値 | 理由 |
|---|---|---|
| ファイル名変更時に内部リンクを自動更新 | オフ | `ID = ファイル名 = id` の三者一致が崩れる。改名は ID の付け替えで、欠番規約に反する |
| 除外ファイル | 置かない | `views/` を除外すると検索・グラフでの二重表示は減るが、A のリンクの起点も見えにくくなる。個人で設定する |

## Obsidian から編集するときのリスク（どの案でも共通）

- **不変層を守るのは pre-commit と CI だけになる。** PreToolUse フックは Claude Code の
  編集しか止めない。Obsidian で LOG や `transcript.md` を書き換えても、コミット時に門で止まる
  だけで、ファイル自体は変わってしまう。LOG を開いて Properties を触らない、を運用で伝える
- **Properties UI で編集すると frontmatter が書き直されることがある。**
  `代替案` のような入れ子のリストは Properties で扱えず、他の項目を UI で触ると
  直列化し直される可能性がある。`miniyaml` は知らない構文で例外を出す（フェイルクローズ）ので
  黙って壊れはしないが、lint の error として返ってくる。DEC はソース表示で編集するのが安全
- **ビューは手で編集しない**規約は Obsidian でも同じ。Stop フックは Claude Code のターン終わりにしか
  動かないので、Obsidian だけで作業した日は `kime views` を手で回す

## B に進むかの判断

グラフとバックリンクが実際に会議の準備で使われるか（`agenda-next` から辿るだけで足りないか）を
A で確かめてから決める。A は生成物しか触らないので戻すのも再生成だけで済むが、B は書式の変更で、
取り消すには全カードをもう一度書き換えることになる。
