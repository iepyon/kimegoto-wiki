## 見て、直さなかったもの（理由を残す）

- **Q の `初出` / `最終言及`、DEC の `決定日`・`会議体`** — `derived_from` → LOG → 会議から導出できる冗長。
  ただし `kime new` が書き、lint（`date-anchors`）が照合する「機械が書き lint は保険」の形に
  収まっているので、2枚書きの害（人が直す）は出ていない。消すと `q-stale` などの計器が導出に
  依存して遅くなるだけ。残す
- **`derived_from` の先頭 = 起票した会議、という並び順の意味** — `Bundle._born_by` / `status` の
  `_born_in` が依存している。明示のフィールド（`起票会議`）にすると多対多の原則（カードに
  `meeting` を持たせない）と衝突する。並び順の規約として `schema.md` にある。残す
- **ACT の `更新履歴`（`- 日付: 内容` の配列）** — キーが日付の1要素マップの列で、形は妙だが
  `kime update --log` が書き、`date-format` が日付を見る。読み手にも分かる。残す
- **TERM の `初出`（LOG 参照）と Q の `初出`（日付）が同名で別の型** — 型ごとにフィールドを
  定義しているので機械は困らない。人が混同する余地はあるが、改名は既存カードの書き換えになる。
  次に TERM を触るときに合わせる
- **`AGD.予定会議` の名前** — agenda-sync で「載った会議」の記録も入るようになり、「予定」は
  名前として狭い。ただし `予定会議` は人が未来の会議を書く欄でもあり、両方の意味を1つの列で
  持つのは「載る会議は機械が決める」原則と合っている。`決着日` が入ったので履歴は引ける。改名しない
