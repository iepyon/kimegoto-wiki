# 利用者の手順を4つに減らした記録（2026-09-23）

`docs/mechanization-20260921.md` が「スキルから道具へ移した記録」。これはその続きで、
**利用者が覚えることを減らした記録**。裏で残る記録（カード・引用・`なぜ` の空欄）は
一切減らしていない。減らしたのは、人が覚える会議 ID・段の順番・コマンドの数。

## 動機

2回の通し実験（`docs/dryrun-20260918.md`、`docs/dryrun-20260923.md`）で、会議1回分に
利用者が出す依頼は次のとおりだった。

```
/segment → 粒度の確認 → agenda-sync --write → /log-cards → /extract（論点ごと）
→ scope-questions --write → verify-quotes --fix → lint → /review → /minutes
```

10段、そのうち会議 ID を打つのが7回。順序の罠が2つ（`agenda-sync` は粒度の確認の後、
`promote-input` は `なぜ` の後）。人が判断する箇所は実は2つしかない（粒度の確認、確認②）のに、
残りの8段の「次は何か」を人が覚えていた。**記録の質はここで決まらない**ので、ここは機械に渡せる。

## 変えたもの

| # | 何を | どこへ | 効く理由 |
|---|---|---|---|
| 1 | 「いまの会議」と「どこまで済んだか」の判定 | `kime status`（`--id` で会議 ID だけ） | ファイルの有無とカードの中身から一意に決まる。人にもスキルにも覚えさせない。途中で切れても「次にやること」から再開できる |
| 2 | Pass 1〜3 の順序と止まる場所 | `ingest` スキル | 利用者の依頼は「取り込んで」の一言になる。判定基準は各パスのスキルにしか無く、`ingest` は順序だけを持つ（`CLAUDE.md` 規約7） |
| 3 | 次回アジェンダと議題の起票 | `agenda` スキル（`minutes` から分離） | 下記 |
| 4 | 会議 ID の省略 | README とスキルの手順から `--meeting` を落とす | `review` / `minutes-input` / `promote-input` / `unknown-terms` は元から最新の会議に落ちる。`new agenda` は `予定会議` が空なら次回に載る |
| 5 | 議題を足すときに聞くもの | 文言と提起者の2つ（会議は聞かない） | 会議 ID は利用者が知らないことが多い。空なら次回に載るので、聞かなくても記録は同じ |

## 判定を変えたもの（暗黙にしない）

### `agenda` を `minutes` から再び分けた

2026-09-21 に `agenda → minutes` と統合した理由は「どちらもカードから読み取り専用で
読み物を出す」だった。その後、議題（AGD）が入って `agenda` は**議題を起票する**（カードを
書く）ようになり、統合の前提が崩れた。`minutes` の description には13個の言い回しが
並び、「議題を足したい」で議事録のスキルが動く形になっていた。

分けた基準: **書く先が違うものは別のスキル**。`minutes` はカードを一切書かない。
`agenda` は議題の起票と、人が言ったときの議題の締めだけを書く。

### `ingest` を足しても、Pass 1 → 2 の人間のゲートは残す

2026-09-21 の記録は「Pass 1→2 のあいだの人間のゲートは、別のスキルに分かれていること自体が
安全装置」としている。`ingest` はこの分割を跨ぐので、安全装置を**スキルの分割から、
止まる場所の明記へ**移した。`ingest` の止まる場所は2つだけ（粒度の確認、確認②の手前）で、
飛ばすことと「確認済みとみなす」ことを禁止事項に書いた。

分割そのものは残している。`/segment` `/log-cards` `/extract` は単独で呼べ、判定基準はそこにしか無い。

### `kime status` は「済」と言わない

人間の判断（粒度の確認が通ったか、確認②を済ませたか）はファイルからは分からない。
だから `status` は**残っているものの数**だけを出す。`なぜ` が空欄のまま残るのは正常な状態で、
「確認②が未完了」ではない（`CLAUDE.md` の「空欄は情報」）。

### 減らさなかったもの

- 確認②の6項目。ここが記録の質そのもの。1つに束ねると人が「はい」で通す
- Pass 3 の「1論点ずつ」。`ingest` の中でも守る
- `scope-questions` の「内容を見てから `--write`」。範囲の問いは顧客に出るので機械で起票しない
